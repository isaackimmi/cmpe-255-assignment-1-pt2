# Project 06 — Anomaly Detection

This project is a deterministic teaching benchmark for global, local-fringe, and clustered anomalies. Its evaluation protocol is deliberately separated into three roles:

- **Clean training normals (600):** fit the scaler and all detectors.
- **Clean calibration normals (200):** select score thresholds without labels.
- **Labeled holdout (300):** 200 normals plus 100 synthetic anomalies, used only for final metrics and the dashboard’s offline replay.

The anomaly generator applies an acceptance rule before assigning mechanism labels: every generated anomaly must have squared Mahalanobis distance at least 8 from the nearest declared normal component. This makes the labels defensible as tail anomalies under the stated synthetic population, while remaining a toy protocol rather than a production claim.

## Methods and comparison

- Isolation Forest: isolates unusual observations using random partitions.
- Local Outlier Factor (LOF): compares local density to neighboring density, configured for novelty scoring on new observations.
- Elliptic Envelope: robust covariance / Mahalanobis-style detector; useful as a simple global elliptical baseline.
- Rank ensemble: averages each detector’s percentile rank relative to clean training scores. It is a candidate combination, not an assumed improvement.

Detector configuration is label-independent. The only contamination value is the fixed `0.10` model prior used by Elliptic Envelope; it is not derived from any label array. The review queue uses an explicit 100-alert benchmark (`precision@K`, `recall@K`, and `F1@K`), and the dashboard also exposes score thresholds calibrated from clean data.

## Run

From this directory:

```bash
python3 -m pip install -r requirements.txt
python3 src/anomaly_experiment.py --output-dir artifacts
python3 -m pytest -q
```

The run writes `artifacts/metrics.json` and `artifacts/anomaly_scores.png`. The experiment is deterministic with respect to the seed and accepts `--seed` for sensitivity checks. The artifact records the seed, split sizes, model configuration, threshold policy, anomaly acceptance rule, and generation timestamp.

## Dashboard

The responsive dashboard loads `artifacts/metrics.json` and presents holdout detector comparison, ROC-AUC, average precision, explicit `F1@K`, category `recall@K`, the saved score map, and an operating-point explorer.

Start a local static server from this directory:

```bash
python3 -m http.server 8000
```

Open [http://localhost:8000](http://localhost:8000). The threshold slider selects an actual percentile of clean calibration scores; the alert-cap slider applies a real cap to the saved holdout predictions. The queue readout is replayed from score-backed operating points generated by Python, not invented by a client-side formula. Holdout labels are used only to calculate the displayed offline precision and recall.

## Evaluation and interpretation

Accuracy is intentionally omitted because the anomaly class is rare. ROC-AUC measures ranking quality, average precision summarizes precision-recall quality under imbalance, and `precision@K`, `recall@K`, and `F1@K` describe the explicit fixed review queue. Category recall shows whether aggregate results hide failure on global, local-fringe, or clustered mechanisms.

The labeled holdout prevalence is a property of this synthetic benchmark, not an observed production prevalence. Thresholds are selected without holdout labels, but the reported holdout metrics are still single-seed estimates. Results should be treated as a method comparison and failure-mode illustration; repeated seeds, uncertainty intervals, and operational cost calibration are appropriate before making deployment claims.
